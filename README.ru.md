# Local Captions для macOS

[English →](README.md)

Локальные субтитры EN/RU с переводом в обе стороны для системного звука любых приложений.
macOS 15+, Apple Silicon. Версия — 0.9.1.

## Запуск

Откройте `dist/Local Captions.app`. Главное окно «Local Captions» открывается при запуске и
при повторном открытии приложения; то же окно — по клику на значок в строке меню (облачко
субтитров, во время записи с красной точкой). В окне: **«Запустить / Остановить»** и три
переключателя, которые работают и во время сеанса:

- **Субтитры** — показать или скрыть плашку. Скрытые субтитры продолжают записываться в
  историю и файл встречи: так удобно писать русскую встречу без субтитров на экране.
- **Перевод** — включить или выключить переводчик. Транскрипция идёт всегда; выключенный
  перевод не загружает модель и не тратит ресурсы.
- **Микрофон** — канал «Я» для созвонов. Bluetooth-наушники при включённом микрофоне
  переходят в режим гарнитуры, и звук становится глуше, поэтому включайте его только на
  созвонах. Выключение на ходу сразу расшифровывает записанное в файл встречи.

Режим выбирается в «Настройки → Распознавание»: **Обучение** (основной) или **Перевод
отдельной дорожкой**. Прежний режим EN+RU стал обучением с выключенным переводом.

- **Обучение** — основной режим: английская и русская речь как есть, без перевода на экране.
  Поэтому его можно не выключать весь день: видео на английском для тренировки и рабочие
  созвоны на русском одинаково пишутся в файл встречи. Используется Ultra без подсказки
  языка; язык каждой фразы определяется по алфавиту. Клик по слову переводит его на другой
  язык в контексте фразы, двойной клик — ещё и всю фразу: английское — на русский, русское —
  на английский. В «Настройки → Распознавание → Переводить на» можно выбрать любой из языков
  HY-MT2 (немецкий, японский, украинский и другие): тогда все фразы переводятся на него, а
  фразы на нём самом — на английский. Выбор применяется сразу, в том числе во время записи. Пока курсор над субтитрами, их строки стоят на месте, а плашка
  раскатывается вниз шторкой: под чертой «эфир» продолжается речь. Когда курсор уходит,
  шторка сворачивается вверх. Под плашкой поэтому зарезервировано место на три строки.
  Карточка с переводом появляется над плашкой, показывает оригинал фразы и подсвечивает её
  слова; в карточке слово можно добавить в словарь.
- **Перевод отдельной дорожкой** — только английская речь: английский сверху, русский
  перевод ниже. Английский текст не сдвигается, когда приходит перевод.

Модель, окна Ultra, переводчик, термины и внешний вид настраиваются в окне
**«Настройки…»**. Окно Ultra у обучения по умолчанию 0,96 с (русскому при 0,64 с ошибок
вдвое больше), у перевода — 0,64 с. Режим, модель и окна применяются при следующем запуске.
Закрытие поповера и окон не останавливает работу: для этого нажмите **«Остановить»**.

Микрофон пишет собственную речь в файл встречи и не выводится в субтитрах. С ним
используется Ultra: оба канала разделяют одни веса, состояния декодера раздельные.
Включить его посреди сеанса можно только при Ultra.

Разрешите приложению **«Только запись системного звука»**, если macOS запросит доступ.
Начиная с 0.6.1 звук захватывается публичным API Core Audio taps (`CATapDescription`,
macOS 14.4+) с приватным tap, невидимым другим процессам; разрешение записи
экрана для захвата не требуется. Tap не отключает звук и не меняет устройство вывода.
Источник звука определяется через Core Audio. Звук браузера идёт из служебного процесса
внутри его пакета; он сопоставляется с самим браузером по пути процесса, поэтому в истории
и файлах пишется «Yandex», а не `…helper`. Настройка **«Определять звучащую вкладку браузера»**
(«Настройки → Источники и файлы») через «Универсальный доступ» находит вкладку с пометкой
о звуке, включая фоновую, и добавляет её название к источнику. Пометка у браузеров разная,
поэтому распознавание эвристическое; если вкладка не находится, кнопка «Сохранить отчёт о
вкладках» пишет `Transcripts/browser-tabs-report.txt` со всеми подписями вкладок.
Названия вкладок попадают в файлы встреч, поэтому настройка выключена по умолчанию.
Названия приложений определяются через Core Audio. Названия окон доступны только
при уже выданном разрешении экрана: ради этой необязательной метаинформации приложение
не запрашивает дополнительный доступ. Название встречи можно ввести вручную.
Если потребуется, закройте и откройте приложение после выдачи разрешения.
Микрофон включается только своей настройкой и также требует разрешения macOS.
До нажатия «Запустить» звук не захватывается.

Если переключатель разрешения включён, но приложение снова его запрашивает после
пересборки, macOS могла сохранить разрешение для предыдущей временной подписи.
Закройте Local Captions, удалите только его запись кнопкой «−» в списке разрешений,
добавьте актуальную `dist/Local Captions.app` кнопкой «+» и откройте её заново.
Для обновлений с сохранением разрешений нужна постоянная подпись Apple Development
или Developer ID. У этой локальной сборки подпись ad hoc; после изменения кода разрешение
может потребоваться заново. Сборка и подпись приложения не меняются во время его работы.

### Окно субтитров

Субтитры идут сплошным потоком с фиксированным числом строк. Новый текст добавляется
снизу; когда появляется новая строка, весь блок плавно сдвигается вверх ровно на одну
строку. Строки выше последней не переносятся заново. Новый абзац начинается с новой строки,
если предложение закончилось и спикер помолчал хотя бы секунду, либо после любой паузы
от 2,5 секунды. Паузы берутся из таймстемпов слов; то же правило собирает абзацы в истории.

- Слова одного обновления распознавания появляются по очереди, а не пачкой
  (настройка «Показывать слова по одному»).
- Последние два слова ещё не завершённой гипотезы приглушены: модель может их поправить.
  Исправленное слово на секунду подсвечивается.
- После 6 секунд тишины плашка гаснет целиком и появляется снова с новой речью.

Высота не задаётся вручную: она считается из шрифта, межстрочного интервала и числа
строк (2–6). Ширину меняют края плашки (ручки видны при наведении) или ползунок в
настройках, 360–1600 pt. Плашку можно перетащить. Пресеты положения: **«Снизу по
центру»** и **«Справа колонкой»**; колонка занимает высоту экрана, и число строк
подбирается само. Положение и размер сохраняются между запусками.
В настройках также есть шрифт (16–44 pt), прозрачность подложки и межстрочный интервал.
Кнопка «Проверить окно субтитров» показывает демо без захвата звука.

### История и словарь

История сеанса открывается отдельным окном из поповера или по ⌘⇧H, когда приложение
активно. В ней поиск по оригиналу и переводу, абзацы с оригиналом слева и переводом справа,
текст можно выделять и копировать. В обучении перевод в истории размыт до клика.
Вкладка «Словарь» показывает слова, сохранённые из карточки, вместе с фразой, где они
встретились; файл — `Transcripts/vocabulary.json`. История доступна и после остановки
до начала следующего сеанса; файлы остаются на диске.

Режим ручной: включайте утилиту для нужного аудио и нажимайте «Остановить», когда
субтитры не нужны. Язык не определяется, звук по языку не отбрасывается.

## Сохранение встреч

Каждое нажатие «Запустить» после успешного начала захвата создаёт отдельный сеанс в
`Transcripts/` рядом с этой инструкцией. Название встречи можно ввести перед запуском;
оно попадёт в имя файлов и заголовок. Без названия используются дата и время.
Кнопка «Открыть папку» в настройках («Микрофон и файлы») открывает эту папку в Finder.

- `.md` — читаемая транскрипция с оригиналом и, в режиме перевода, переводом,
  временными метками и возможными источниками.
  Обновляется по мере готовности реплик и при остановке.
- `.jsonl` — журнал событий для анализа. Каждая строка — самостоятельный JSON:
  `session_start`, `english_final` (режим перевода), `transcription_final` (EN+RU), `translation`, `translation_error`,
  `interrupted_caption`, `session_end`. Реплика имеет постоянный `caption.id`:
  берите последнее событие с этим ID, чтобы получить её актуальный текст и перевод.
  Даты записаны в ISO 8601; `firstSeenAt` — время первого появления текста, не точная
  граница аудиофрагмента. В версии формата `schemaVersion: 3` поле `session.mode` равно
  `translation`, `transcription` или `learning`; `caption.original` хранит оригинал на любом языке.
  Старое поле `caption.english` сохранено для совместимости и тоже содержит оригинал.
  `microphone_transcription` добавляет отдельный канал: `caption.channel: microphone`,
  `audioStartAt`/`audioEndAt` — время звука. Для новых системных реплик `channel: system`.
  Старое отсутствующее поле `channel` также означает системный звук. Модель переводчика
  записана в `session.translationModel`.

Оригинал сохраняется до готовности перевода. При остановке сохраняется
последний незавершённый фрагмент; русский перевод, который не успел завершиться, может
отсутствовать. После аварийного завершения остаются уже записанные события и последняя
Markdown-копия, события `session_end` может не быть. Сохраняются все результаты
распознавателя во время включённого захвата; язык входа не проверяется.

### Термины

`Transcripts/glossary.txt` — ваши термины для перевода, строки вида `витрина = data mart`.
Файл создаётся при первом запуске с несколькими примерами и открывается из настроек
(«Распознавание → Открыть glossary.txt»). Термины работают в обе стороны и подсказываются
HY-MT2 только для фраз, где они встречаются; русское слово находится и в других падежах
(«витрину», «витрины»). Клик по слову из словаря терминов отвечает сразу, без модели.
Словарь хранит пары «русский — английский», поэтому работает только при переводе на эти
два языка.
В режиме обучения `caption.russian` в журнале содержит перевод на другой язык, а
`caption.translationLanguage` говорит, на какой: код языка, по умолчанию `en` для русской речи
и `ru` для английской.

### Статистика распознавания

При каждой остановке в `Transcripts/metrics.jsonl` дописывается строка с итогами сеанса;
последние сеансы видны во вкладке «Статистика» настроек. Звук и текст в этот файл не пишутся.

- `displayLatency` — секунды от конца слова в захваченном звуке до момента, когда на
  экране появилось его окончательное написание (p50, p90, p95, max). Конец слова берётся
  из таймстемпов токенов модели, момент прихода звука — из часов захвата. Слова, которые
  ждали из-за паузы в обучении, не учитываются.
- `revisedWords` / `shownWords` — сколько показанных слов потом изменилось или пропало.
  Рост последнего слова по мере произнесения правкой не считается.
- `translationLatency` — от завершения фразы до готовности перевода.
- `learning` — фразы, перевод которых понадобился, просмотренные слова, слова в словаре,
  число и длительность пауз.
- Настройки, с которыми получены цифры: модель, `ultraChunkSeconds`, `wordPacing`.

Ultra декодирует звук окнами: слово ждёт в среднем половину окна, плюс 0,32 с правого
контекста и время расчёта. По умолчанию окно 0,64 с (было 1,28 с); выбирается в настройках
среди 0,48 / 0,64 / 0,96 / 1,28 с. Замер — в `docs/window-2026-11-17.md`.

### Канал микрофона

Микрофон пишет временные 30-секундные CAF-фрагменты в
`Transcripts/.pending-microphone/<session-id>/`. Через **три минуты без слышимого системного
звука** начинается их расшифровка. Поступление нулевых пакетов не считается звуком;
энергетический порог — 1e-7, это не детектор языка или собеседников. С появлением звука
новые фоновые задания откладываются; уже начатый фрагмент может завершить обработку.
При «Остановить» захват прекращается сразу, затем дорасшифровывается остаток очереди.
Состояние и число ожидающих фрагментов показаны в управлении.

Текст добавляется в общий Markdown/JSONL по времени записи с меткой **«Я · микрофон»**.
Аудиофайл удаляется только после успешной записи и синхронизации текста в журнале.
При ошибке фрагменты и сведения о связанном журнале остаются в этой папке; автоматического
восстановления после аварийного выхода пока нет. Это временные локальные аудиофайлы,
а не постоянный архив записи встречи. Float32 mono 16 кГц требует около 230 МБ на час
непрерывного ожидающего аудио; полностью тихие фрагменты удаляются без распознавания.
Пока системный звук непрерывен, очередь может расти на диске.

Времена системных реплик по-прежнему относятся к появлению текста; у «Я» есть время
исходного аудио, поэтому объединение двух каналов приблизительное, не до аудиосэмпла.
Это разделение по устройству ввода, а не определение личности по голосу: звук из колонок
может попасть в микрофон. Наушники помогают избежать дублирования.

В источники попадают приложения/процессы с активным аудиовыходом, а также доступные
названия их окон. Для этого не используется микрофон, изображение экрана или Accessibility.
Это **кандидаты**, а не доказанное соответствие реплике: приложение может держать выход
открытым в тишине, несколько приложений могут звучать одновременно, а браузер не раскрывает,
какая именно вкладка воспроизводит звук. Название окна может оказаться названием встречи,
но гарантировать это для всех приложений нельзя. При отсутствии данных источник остаётся пустым.

Приложение использует `.runtime` в этой папке. Не удаляйте её. После перемещения проекта
пересоберите приложение командой `python3 scripts/build.py`.

## Локальные модели

- Parakeet Ultra 600M, Core ML — распознаватель английской и русской речи. Окно
  0,64–2,0 с (по умолчанию 0,96 с в обучении и 0,64 с в режиме перевода), левый контекст
  6 с, правый 0,32 с. Изменяемый хвост показывается сразу; для перевода используются
  только подтверждённые токены.
- HY-MT2-1.8B Q4_K_M — переводчик EN ↔ RU, llama.cpp/Metal. Официальный файл весов —
  1,13 ГБ; ревизия и SHA-256 сохранены в `.runtime/models/hymt/download-manifest.json`.
  llama.cpp закреплён на b12415. Контекст 2048 токенов, один слот, два CPU-потока,
  модель выгружена на Metal, температура 0. Две предыдущие фразы того же направления
  используются как контекст. Прогретый процесс живёт до остановки.

Выбор моделей в настройках сохранён: чтобы сравнить другой распознаватель или переводчик,
добавьте вариант в `RecognitionModel` (и его загрузку в `Recognition.load`) или в
`TranslationModel` и `TRANSLATORS` в `backend/worker.py`. Parakeet Realtime 120M и Argos
удалены в 0.8: Realtime понимает только английский, Argos переводит только EN → RU.

При остановке завершаются задачи, освобождаются модели и завершается процесс переводчика;
до этого новый запуск недоступен. При обычном выходе приложение также дожидается очистки.
Core ML и macOS могут сохранять системные кеши: показатели памяти не обязаны немедленно
вернуться к исходным. Название модели сохраняется в Markdown и метаданных сеанса JSONL.

Whisper Tiny больше не загружается приложением и не участвует в обработке аудио.
Его ранее скачанные файлы оставлены для диагностических эталонов.

Модели скачиваются при установке. Во время работы загрузка отключена; аудио и текст
не отправляются на внешние серверы. Swift общается с Python через pipe; HY использует
приватный Unix-сокет в каталоге с доступом только текущему пользователю, TCP-порт не открыт.
Системный звук не записывается на диск; временное аудио создаёт только включённый канал
микрофона. Текст и доступные сведения об источниках сохраняются в `Transcripts/`.
Остановка завершает захват, очередь микрофона, выбранный переводчик и его дочерний сервер.

### Нагрузка на Mac

Замер на MacBook Pro M2 Pro (32 ГБ) во время созвона: `ps`, `footprint` и `powermetrics`.

| | Идёт запись | Запись остановлена |
|---|---:|---:|
| Процессор, процесс Local Captions | 15–20% одного ядра, в пиках до 45% | 0% |
| Память | ~190 МБ приложение + ~770 МБ переводчик | ~180 МБ, переводчик выгружен |
| Нейроускоритель (распознавание) | +0,2 Вт | 0 Вт |
| Процессор и видеоядро всей системы, Вт | не отличается от выключенного приложения в пределах секундных колебаний | так же |

Скорость воспроизведения почти не влияет: на видео x2 цифры те же, потому что распознаватель
обрабатывает окна фиксированной длины. Для сравнения: само приложение созвона занимало
нейроускоритель примерно на 0,9 Вт, видимо шумоподавлением или эффектами фона.
До 0.8.1 после остановки записи приложение могло крутить два ядра вхолостую: обработчик
вывода переводчика не отключался в конце потока.

## Сборка

Требуются Xcode с Swift 6.2+ и [uv](https://docs.astral.sh/uv/).

```sh
python3 scripts/setup.py
```

Скрипт создаёт `.runtime/` рядом с проектом: Python-окружение для переводчика, FluidAudio
закреплённой ревизии, Parakeet Ultra (около 630 МБ, ревизия
`95eaa59a39d4394f047a4dc5cce480388a60d1b6`) и HY-MT2 с llama.cpp (около 1,1 ГБ). Хеши файлов
сохраняются в `download-manifest.json` каждой модели. Затем собирается
`dist/Local Captions.app`. Во время работы приложения ничего не скачивается.

Для повторной сборки без скачивания моделей:

```sh
python3 scripts/build.py
```

Чтобы подготовить сборку без изменения работающего приложения:

```sh
python3 scripts/build.py --output '.runtime/release-candidate/Local Captions.app'
```

## Ограничения первой версии

В режиме EN → RU вход рассчитан на английский; русская речь может давать ошибочный
английский текст. Для русских встреч используйте **EN+RU transcription**. У Ultra в этом
режиме снято ограничение на латиницу: отдельного определения языка нет, модель может
транскрибировать и другие поддерживаемые языки. Шум, музыка, имена и технические
термины могут распознаваться неверно. Обработка не разделяет одновременно говорящих людей.
Переводчик компактный: термины и оборванные фразы могут переводиться неестественно.
Это локально подписанная сборка, не notarized-дистрибутив для сторонних компьютеров.
Показ поверх полноэкранного контента зависит также от разрешений и поведения macOS Spaces.

Скорость нужно оценивать на реальном созвоне: время обработки моделей отличается от
задержки между произнесённым словом и готовой строкой, в которую входит ожидание контекста.
Результаты отдельного поточного замера и обзор исследований сохранены в
`docs/latency-2026-11-17.md` (исторический замер до версии 0.3).

В версии 0.3 повторены те же восемь фрагментов в ручном режиме:
**EN: медиана 0,47 с, p95 0,78 с**, 36 из 39 выбранных выражений вместо прежних 24.
Отсчёт приблизительный: от автоматической оценки конца слова до данных интерфейса,
без захвата системного звука и отрисовки. Перевод ждёт более длинного контекста:
медиана готовности RU блока относительно исходных слов — 4,72 с, p95 — 10,43 с.
[Описание изменений, методики и результатов](docs/manual-mode-2026-11-17.md).

Исторический замер версии 0.2 с автоопределением языка:
[восемь фрагментов с шестью голосами](docs/accents-2026-11-17.md)
(США, Лондон, Ирландия, Индия). EN: медиана 0,96 с, p95 1,59 с до данных интерфейса.
В той версии поток сохранял 24 из 39 выбранных ключевых выражений против 36 из 39
на целых файлах: выявлены потери в языковом фильтре и обработке коротких фраз.
Сырые аудио, метаданные и результаты находятся в `.runtime/accent-benchmark/`.

## Выполненные проверки

В 0.8.0 прошли **42 теста** (ещё 10 опциональных пропускаются без переменных окружения):
часы аудио и сопоставление слов со звуком, метрики правок и задержки, журнал `metrics.jsonl`,
расчёт высоты плашки, пословный показ, приглушённый хвост, подсветка правок, абзацы,
пауза обучения. На реальном звуке проверены метрики для Ultra и Realtime и окно Ultra
([замер](docs/window-2026-11-17.md)); отрисовка дорожек проверена снимками NSPanel.
Поповер, окно настроек, наведение и клик по словам в живой панели, а также захват
системного звука в сборке 0.8 вручную пока не проверялись.

В 0.7.0 прошли **32 проверки**: 30 тестов состояния/журнала/геометрии/аудио,
нативное уменьшение невидимого NSPanel с длинной двуязычной историей и интеграция
режима обучения с реальными Ultra/HY на синтетическом аудио. В установленном приложении
проверены три режима, ползунки шрифта/высоты, раскрытие перевода кликом и открытие истории
жестом прокрутки из живого демотекста. Захват при UI-проверке не запускался.
[Изменения и результаты 0.7](docs/presentation-2026-11-17.md).

В версии 0.6: **23 теста и пять интеграционных проверок прошли**. Проверены абзацы,
высота окна, временные фрагменты микрофона, порог тишины, объединение каналов с записью
журнала до удаления аудио, одновременный ASR двух каналов с общими весами Ultra,
потоковый EN с HY-MT2 и завершение его сервера. Источником микрофонного теста был
синтетический аудиофайл. В интерфейсе проверены новый выбор переводчика, включение
микрофона с принудительным выбором Ultra и изменение высоты 360→480 pt. Проверка
физического микрофона ещё не завершена; сам оверлей полностью через UI ещё не проверен.
Сравнение шести тестовых фраз: HY — медиана около 0,34 с, Argos — 0,18 с на готовый
перевод, без ожидания речевого контекста. Это не оценка WER или p95 задержки живых субтитров.
[Изменения и результаты 0.6](docs/meeting-2026-11-17.md).

В 0.6.1 захват заменён на Core Audio taps: доступ к экрану больше не требуется.
26 тестов прошли, в том числе новые проверки аудиоформатов и смешивания обоих каналов.
Пакет установлен в `dist/Local Captions.app`, копия кандидата находится в
`.runtime/audio-only-candidate/Local Captions.app`. После повторного разрешения
микрофона живой тест прошёл при выключенном доступе к экрану: 11 системных фрагментов
с переводом HY-MT2 и 4 микрофонных сохранены в общий журнал. Остановка закрыла сеанс,
обработанные CAF удалены, процессы перевода завершены. Содержание в отчёт не выводилось;
точность речи и полная задержка в этом тесте не измерялись.

В версии 0.5.1 устранена обратная связь между шириной окна и настройкой: события
ручного изменения размера больше не порождают повторные команды изменения окна,
отложенные запросы ползунка объединяются и используют актуальную ширину. Это исправляет
уезжание окна и возможное зацикливание главной очереди. Чтение аудио вынесено из MainActor;
обновления текста обслуживаются и в режиме отслеживания меню/окна. Очередь нормализует
аудио в блоки по 320 мс и ограничена 15,36 с, вместо прежних 200 пакетов неизвестной длины.
Настоящее переполнение по-прежнему останавливает захват с ошибкой, не скрывая потерю звука.
**17 тестов и три интеграционные проверки прошли**. Поточный тест RU→EN→RU использует
5-мс пакеты и 8 секунд вложенного event-tracking цикла: текст появляется во время
отслеживания, распознавание не останавливается. Дополнительно в запущенном приложении
при активном захвате 16 раз изменена ширина ползунком без остановки распознавания;
нативное меню приложения открывается и закрывается через действие отмены.
Физическое перетаскивание ручки и меню значка в строке состояния полностью через UI
не подтверждены. Логи: `.runtime/interaction-tests.log`, `.runtime/interaction-audio-probe.log`.

В версии 0.5: **11 тестов состояния/журнала/режимов/геометрии окна**, а также три
интеграционных теста с Core ML прошли без ошибок. Последовательность синтетических
записей «русский → английский → русский» (20,83 с) распознана Ultra без процесса
переводчика; транскрипция сохранена в Markdown/JSONL. Повторно проверены обе модели
с переводом и освобождение распознавателя после остановки. Это не оценка качества
на реальной русской встрече. Ползунок ширины и чекбоксы проверены в интерфейсе;
геометрия боковых ручек — тестами. Живой захват сборки 0.5 отдельно не проверялся.
[Изменения и проверки версии 0.5](docs/modes-2026-11-17.md).

Результаты сравнения двух моделей, методика и ограничения измерений:
[отчёт версии 0.4](docs/models-2026-11-17.md). Ultra: EN около 0,62 с по медиане,
1,20 с на p95, 37/39 выбранных выражений; Realtime: 0,47 с, 0,78 с, 36/39.
Ultra чаще исправляет хвост текста, поэтому Realtime сохранён вариантом по умолчанию.

Для 0.4 добавлены проверки исправления изменяемого хвоста Ultra без изменения
подтверждённого текста, границ стабильных предложений и записи названия модели в журнал.
Поточные проверки на реальных записях запускаются с `LOCAL_CAPTIONS_PROBE_MODEL=ultra`;
без этой переменной используется Realtime.

В версии 0.3: пять тестов состояния/журнала/границ слов и потоковый прогон восьми
реальных записей без ошибок, сборка и проверка подписи `.app`, открытие приложения
в ручном режиме в состоянии «Остановлено». Живой захват новой сборки отдельно
не проверялся; результаты ниже относятся к более ранним проверкам.

На macOS Sequoia 15.6: сборка `.app`, проверка подписи, визуальная проверка окна,
пять XCTest-тестов (независимое истечение фрагментов с сохранением истории, границы полных слов,
отклонение запоздалых результатов, повторное открытие истории после остановки и запись
EN/RU/источников с незавершённым хвостом в Markdown/JSONL). Синтетические записи созданы системными голосами Samantha
и Milena. Английская распознаётся и переводится локально.
Полная обработка английского файла длиной 5,15 секунды заняла около 2 секунд вычислений
после прогрева. Это не измерение задержки живых субтитров.

В версии 0.2 проверен живой путь через ScreenCaptureKit: воспроизведение синтетической английской
записи через `afplay` создаёт английские строки и русский перевод в окне субтитров.
При последующем воспроизведении русской записи приложение показывает «русская речь
пропускается», новые субтитры не появляются, прежнее окно скрывается. Нажатие
«Остановить» во время воспроизведения возвращает состояние «Остановлено» и завершает
процесс локального обработчика. Доступ проверен на одной неизменной подписанной сборке.
В версии 0.2 дополнительно проверены прокрутка демоистории в интерфейсе, возврат к эфиру
и прозрачное окно с отдельными подложками. Живой тест создал Markdown/JSONL с четырьмя
парами EN/RU и событием завершения сеанса; источник без приложения определяется по PID.
Повторный живой тест окончательной сборки подтвердил две пары EN/RU, читаемую подпись
«Процесс …» у `afplay`, сохранение обеих пар в Markdown/JSONL и завершение журнала при остановке.

Повторить проверку на файле можно собранной программой:

```sh
.runtime/swift-build/release/LocalCaptions --benchmark /absolute/path/to/audio.wav "$PWD/.runtime"
```

Для тестов состояния субтитров используется XCTest (Swift Testing не задействован):

```sh
swift test -c release --disable-swift-testing --scratch-path .runtime/swift-build
```
