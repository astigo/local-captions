# Окно Ultra и задержка появления слов

Замер от 17 ноября 2026 года на том же стенде, что и `latency-2026-11-17.md`: две синтетические
записи голоса Samantha по 62 слова (≈200 и ≈300 слов/мин), по два прогона каждой, PCM подаётся
в реальном времени через неизменённый конвейер `Recognition` → `CaptionStore`.
Отсчёт — от конца исходного слова (границы оценены автоматически Whisper Tiny).
Это задержка обновления данных, без отрисовки на экране.

Ultra декодирует звук окнами `левый контекст 6 с + окно + правый контекст 0,32 с`.
Слово ждёт, пока заполнится окно (в среднем половину), затем правый контекст и расчёт.
`hypothesisChunkSeconds` в этом пути FluidAudio не используется.

| Окно Ultra | Первое появление слова, p50 / p95 | Интервал обновлений | Расхождение с текстом | Слов сопоставлено |
|---|---:|---:|---:|---:|
| 1,28 с (было) | 0,72 / 1,30 с | 1,28 с | 0% / 0% | 62 / 62 |
| **0,64 с (по умолчанию)** | **0,32 / 0,67 с** | 0,64 с | 1,6% / 0% | 62 / 62 |
| 0,48 с | 0,29 / 0,65 с | 0,48 / 0,33 с | 1,6% / 4,8% | 62 / 61 |

Расхождение указано отдельно для записи 200 и 300 слов/мин. 1,6% — одно слово из 62.
Перегрузки не было: максимальное опоздание подачи пакета 5–30 мс.
Правок уже показанного английского текста не было ни в одной конфигурации
(`stable_lag` совпадает с `first_lag`).

Вывод: окно 0,64 с вдвое сокращает задержку почти без потери точности. Окно 0,48 с почти
ничего не добавляет по скорости, но на быстрой речи ошибок становится больше и вдвое растёт
нагрузка. Синтетический голос — не созвон: окончательный выбор делать по `metrics.jsonl`
на реальных сеансах. Окно меняется в настройках, вкладка «Распознавание».

## Метрики приложения на том же звуке

Опциональный тест `LatencyProbeTests/testInAppMetricsOnRealAudio` подаёт запись 200 слов/мин
в реальном времени через `LiveAudioInput` → `Recognition` → `LivePresenter` и берёт итог из
`SessionMetrics`, то есть тех же цифр, что пишутся в `metrics.jsonl`.

| Конфигурация | Слов со временем звука | Задержка до экрана p50 / p95 | Правки |
|---|---:|---:|---:|
| Ultra 1,28 с, слова по одному | 62 / 62 | 1,17 / 1,50 с | 1 / 62 |
| Ultra 0,64 с, пачкой | 63 / 63 | 0,62 / 0,91 с | 1 / 63 |
| Ultra 0,64 с, слова по одному | 63 / 63 | 0,76 / 1,00 с | 1 / 63 |
| Realtime 320 мс, пачкой | 62 / 62 | 0,49 / 0,65 с | 0 / 62 |
| Realtime 320 мс, слова по одному | 62 / 62 | 0,64 / 0,78 с | 0 / 62 |

Конец слова здесь — таймстемп последнего токена модели, а не граница Whisper, поэтому
абсолютные значения на 0,3–0,45 с выше внешнего замера. Сравнивать стоит строки между собой.
Пословный показ стоит около 0,14 с медианы; это цена плавности, он выключается в настройках.
Строки «Ultra 1,28» и «Realtime, слова по одному» сняты с первой версией показа, которая
растягивала пачку на 0,8 с; в итоговой версии растяжка 0,45 с (строка «Ultra 0,64, слова по одному»).

Сырые данные: `.runtime/latency-exp/ultra-*/` (`trace.json`, `summary.json`, `words.csv`).

```sh
LOCAL_CAPTIONS_PROBE_MODEL=ultra LOCAL_CAPTIONS_ULTRA_CHUNK=0.64 \
LOCAL_CAPTIONS_PROBE_MANIFEST="$PWD/.runtime/latency-exp/ultra-0.64/manifest.json" \
LOCAL_CAPTIONS_PROBE_RUNTIME="$PWD/.runtime" \
swift test -c release --disable-swift-testing --disable-sandbox \
  --scratch-path .runtime/swift-build --cache-path .runtime/swift-cache \
  --filter LatencyProbeTests/testRealtimeLatencyProbe
.runtime/venv/bin/python scripts/analyze_latency.py .runtime/latency-exp/ultra-0.64
```

## Русская речь и двуязычные режимы

Обучение и EN+RU распознают обе речи, поэтому Ultra работает без подсказки языка.
Английский от этого не страдает: при окне 0,64 с ошибок 1,6% и 0%, первое появление слова
p50 0,32–0,33 с, как с подсказкой. А русскому короткое окно вредит. Текст из 87 слов рабочей
речи прочитан голосом Milena (macOS) на двух скоростях и подан через обучение:

| Окно Ultra | Ошибки, 175 сл/мин | Ошибки, 215 сл/мин |
|---|---:|---:|
| 0,64 с | 12,7% | 15,2% |
| **0,96 с** | **6,3%** | **10,1%** |
| 1,28 с | 5,1% | 10,1% |
| 2,0 с | 6,3% | 8,9% |
| 3,0 с | 6,3% | 8,9% |

Английский при 0,96 с: ошибок 1,6% и 0%, первое появление слова p50 0,41–0,50 с, p95 0,86–0,98 с.

Поэтому у двуязычных режимов своё окно, по умолчанию 0,96 с, а у английского режима
«Перевод» — 0,64 с. Оба меняются в настройках. Данные: `.runtime/latency-exp/russian-window/`
и `.runtime/latency-exp/ultra-0.96-nohint/`.
